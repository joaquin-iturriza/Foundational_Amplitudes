Python asks `siteconf` for paths: `siteconf.PROJECT_DIR`, `siteconf.SWEEP_DIR`, `siteconf.DATA_DIR`;
`siteconf.resolve(cfg)` fills the site-owned half of a sweep config (paths, `cluster` directives, `${PROJECT_DIR}` /
`${SWEEP_DIR}` / `${DATA_DIR}` / `${SCRATCH}` expansion, re-rooting a config generated on another site);
`siteconf.slurm_header(cluster, job_name, out, err)` renders the `#SBATCH` block for the site it runs on,
`siteconf.cpu_header(...)` the CPU-partition one. Recipe runs read `$WORK/datasets` and the cache under `$SCRATCH`;
`DATA_DIR` is the same `datasets` dir on every site. The old `data_path: data/` default is per-checkout and empty on
the clusters: use recipes. Every job script starts with

```bash
_CCORCH_ROOT="${CCORCH_PROJECT_DIR:-${SLURM_SUBMIT_DIR:-$(cd "$(dirname "${BASH_SOURCE[0]:-$0}")/.." && pwd)}}"
source "$_CCORCH_ROOT/sites/activate.sh"
cd "$PROJECT_DIR"
```

(SLURM runs a copy of the script from its spool, so `$0` cannot locate the checkout; `site submit` exports
`CCORCH_SITE` and `CCORCH_PROJECT_DIR`.)
