paths: scripts/publish_main.sh, scripts/fold_worktree.sh, scripts/remove_worktree.sh, worktrees/**
cmds: \bgit\s+(worktree|merge|checkout|branch|rebase|push)\b
---
- `trunk` is the development trunk and what every site checks out (`site sync <site> FA` pushes it and fast-forwards
  the site's copy); everything lives there: core code plus `tools/`, `tests/`, `sweep/`, `scripts/`, `attribution/`,
  `data/` scripts, `notes/`, `CLAUDE.md`, recipes, `sites/`. No per-site branches: a site's differences live in
  `sites/sites.yaml`. `git push` mid-turn is allowlisted; already-committed work is pushed at the end of every turn.
- `main` is the public, stripped-down core, a build artifact of `trunk` regenerated by `scripts/publish_main.sh` from
  the `PUBLIC_PATHS` allowlist (core run path + `config/` + `models/` + `IntrinsicDimDeep/` + example `recipes/` +
  README); `--no-push` to review first. To change what is public, edit the allowlist and re-publish; never merge
  `trunk → main`.
- Retired `ccin2p3`, `jeanzay`: still on GitHub, no commits `trunk` lacks.
- Worktrees: `git worktree add worktrees/wt-<feat> -b <feat> trunk`, implement and verify there, merge into `trunk`,
  then `bash scripts/remove_worktree.sh <wt>`, never `git worktree remove` by hand. Merging brings back code only:
  results, run dirs, eval `.npz`, satlogs, datasets and figures are gitignored and die with the worktree; the script
  folds them into the trunk (`scripts/fold_worktree.sh`), removes the worktree only when every untracked file has an
  identical trunk copy, and deletes the merged branch. Quick standalone edits on trunk are fine.
- Visibility: one GitHub repo, so all branches share visibility; making it public exposes `trunk` and the retired
  branches too (only `main`'s tree is stripped). A truly private dev branch would need a separate repo.
- `.fuse_hidden*` and `._*` files are filesystem leftovers: ignore them.
